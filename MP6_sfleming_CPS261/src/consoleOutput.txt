Explanation:
The different synchronization types result in different behaviors for the threads performing their tasks. When no synchronization is used, there are multiple issues that show up. You can run into issues with data consistency when another thread modifies the shared data before the first can see the changes, so each thread no longer has an accurate count of how many tasks have been completed. 
You can also run into data issues when multiple threads try and access/write to the same shared data simultaneously, which could ruin data integrity or even cause the data to become damaged unexpectedly, leading to data loss. For method synchronization, this locks out the entire method so that only one thread can access it at a time. 
This is good for data integrity since it means that there will only ever be one thread executing the method in question, however, it ultimately defeats a lot of the performance improvements that come from multithreading since you are effectively just creating a queue that is waiting to take turns with their task. This makes the process synchronous, and can be seen by how the threads largely operate in order at almost the same pace as if it were a single thread performing the operation. 
Block synchronization is great when only part of the code inside the method needs to be protected. For the code in this project, it means that the threads can wait their 100ms asynchronously, improving performance. This is seen in the console output where, despite the threads not performing their tasks in order, data integrity is still maintained and processed in the correct oreder.
